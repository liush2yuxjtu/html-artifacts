Rule

核心原则

数据留在本地，计算去找数据。

云端只获得完成当前任务所需的、最小范围的工具调用能力。

不要把整个 .env、Keychain、数据库 dump、用户目录或浏览器 profile 长期复制到云端。

Capabilities

需要准备的 6 个能力

1. 云端执行

Bash、Git、构建、测试、部署和持久化工作区。

2. 私有网络

Tailscale Tailnet 连接云端与本地设备。

3. 本地 MCP

文件、数据库、本地 API、测试数据和内部服务的受控访问。

4. 三类浏览器

匿名、持久登录、一次性自动化 E2E 浏览器。

5. 凭证代理

按任务解析和使用凭证，而不是永久复制凭证。

6. 跨设备状态

Airtable 保存项目、handoff、运行记录、笔记与证据索引。

Setup

逐步启用

1

准备 Grokbot 云端运行时

确认可从 ChatGPT 调用 Bash、Git、持久工作目录、浏览器和自动化测试。硬件规格以你当前 Grokbot 实例的实际状态为准，不在这里假设。

2

把 Grokbot 加入 Tailnet

优先使用 Tailnet 内部访问。只有确实需要互联网主动访问本地服务时才使用 Funnel。

Tailscale Serve · Tailscale Funnel

3

在本地暴露最小 MCP 能力

例如 read_project_file(path)、query_database(readonly_sql)、get_test_fixture(id)、resolve_secret(name)。默认只读，写操作单独授权。

4

分离三类浏览器

匿名浏览器用于公共网页；持久登录浏览器保存 SaaS session；自动化测试浏览器每次创建干净 context，避免污染你的日常登录状态。

5

接入 Airtable 控制平面

用来同步 Projects、Handoffs、Shared Context、Agent Runs、Secrets Index、运行证据和环境状态。不要把大文件或原始敏感数据塞进 Airtable。

6

把统一能力注册回 ChatGPT Chat

ChatGPT 最终只需要看到稳定工具：bash、browser、webapp_test、local_data、secret、git、deploy。底层机器和路由由运行时处理。

Browser

浏览器隔离

匿名浏览器

无登录态、干净 profile。用于公共网页、抓取、视觉检查。

持久登录浏览器

保存 GitHub、Vercel、Airtable 等会话。登录/2FA/CAPTCHA 可以由 Human takeover 完成。

自动化 E2E 浏览器

每次测试隔离 context。用于 Playwright/webapp testing、注册流、破坏性或可重复自动化。

Security

Tailnet vs Funnel

默认：Tailnet / Serve。 只允许 tailnet 内的设备访问本地服务。

必要时：Funnel。 Funnel 会把指定本地服务暴露到公网，所以只应用在确实需要公网 webhook / callback / externally reachable MCP endpoint 的服务上，并限制路径、端口和权限。

不要把“用了 Tailscale”理解为“所有 Funnel 服务都是私有的”。Funnel 是公网入口；Serve 才是 tailnet 内部共享。
Contract

建议 Runtime Contract

runtime:
  shell:
    bash: true
  workspace:
    persistent: true
    git: true
  network:
    tailnet: true
  browsers:
    anonymous: ephemeral
    authenticated: persistent
    testing: isolated
  local_resources:
    filesystem: mcp
    database: mcp
    services: mcp
  secrets:
    source: local
    exposure: per-task
    cloud_persistence: forbidden
  state:
    control_plane: airtable
Acceptance

验收标准：每项都要有操作、通过条件和证据

不要把“配置存在”“进程启动”“build green”“deployment READY”当成完成。缺少可复查 evidence 的能力一律标记为 UNVERIFIED。

0 / 10 已完成

READY 门槛：10 项全部通过；无 secret 泄漏；无整库/整目录私密数据复制；三类浏览器隔离；Tailnet 断开测试证明无公网旁路；至少完成 1 次真实项目闭环。最终必须输出“能力 / 状态 / evidence / 风险 / 下一步”表格。

目标不是简单安装工具，而是完成并验证一个可实际使用的 Personal Cloud Coding Fabric：

ChatGPT Chat
→ Grokbot 云端 Coding Runtime
→ Bash / Git / Persistent Workspace / 三类 Browser / Web App Testing
→ Tailscale Tailnet
→ 本地 MCP / 私密数据 / 凭证 / 本地服务
→ Airtable 跨设备 Control Plane。

执行要求：
- 优先读取现有配置和真实运行状态，不要从零重建已经存在的基础设施。
- 私密数据默认留在本地；云端通过受控 MCP / Tailnet 调用，不要把完整 .env、Keychain、数据库 dump 或浏览器 profile 复制到云端。
- 默认使用 Tailnet/Serve 做私有访问；只有公网回调确实需要时才使用 Funnel。
- 把浏览器明确分成：匿名浏览器、持久登录浏览器、隔离自动化 E2E 浏览器。
- 凭证按任务解析使用，不进入 repo、日志、artifact 或长期云端文件。
- Airtable 只作为跨设备控制平面和状态索引，不作为原始私密数据存储。
- 最终从 ChatGPT Chat 侧暴露稳定能力：bash、git、browser、webapp_test、local_data、secret、deploy。
- 每一步都要真实验收，不要用“配置存在”“build green”“服务启动”代替端到端 runtime evidence。
- 若你已有 Grokbot / Tailnet / 本地机器 / Airtable / MCP 基础设施，先复用和审计，再补缺口；不要复制我的私密数据、凭证或机器身份。
- 完成后给出：当前架构、已验证能力、未验证能力、风险、真实 runtime evidence，以及下一步最小补齐项。

逐项梳理

Element原来的播片感现在已经改成这次最终要求状态
1. Edit Like an Expert Editor
Best Moments		页面展示结果/最终 clip，容易像在看别人编辑。结果先被 Hold。用户点击 Send 后，原来的 final clip 和 playhead 自动继续播放。保持当前方案。 1 次点击即可，后面自动演完。已符合
2. AI Motion Graphics已有 motion cards / Remotion 结果容易直接呈现成展示动画。结果先显示为 pending；用户点击 Generate 后，原来的结果 cards 在原位置 Reveal / 强调。保持当前方案。 点击 Generate 后允许动画自动完成。已符合
3. Text-Based Editingfiller words 的清理过程如果自动发生，会像录屏。先回到 raw transcript；用户点击 Send / Clean 后，filler words 按顺序自动消失，timeline 自动变短。保持当前方案。 不需要用户一个个删词。已符合
4. Auto AI Captions当前原生 caption preview 会自己播放，仍有明显“播片”感。旧 intent 里是“保持原生，不改”。补一个极轻触发：用户点击任意 Caption preset / Preview 一次后，再开始自动播放字幕动画；左右切换仍保持原生。需补触发
5. AI Image Generation一开始就看见生成结果，像展示成片。先显示 before/source image；点击 Generate → 短 loading → 自动换成原来的 generated result。保持当前方案。 1 次点击后自动完成。已符合
6. AI Video Generation生成视频直接展示/播放，像视频广告。先显示 reference image；点击 Generate → loading → 自动 Reveal 并播放原 preview video。保持当前方案。 不要求用户再手动 Play / scrub。已符合
7. AI Music Generatorsilent source / waveform 如果自己切换，仍然像自动演示。已有 Send 按钮：点击后 loading → 自动 Reveal waveform / generated music UI。保持一键触发。 若原页面仍有进入视口就开始的视觉动画，先暂停，直到用户第一次点 Send。需确认首帧
Pricing不是功能播片。保持 Monthly / Annual 原生交互。不纳入这次改造。保持

不做的事情

明确排除
不强制把每段 Demo 做成“用户操作 → 产品响应 → 用户再操作 → 产品再响应”的多轮 state machine。除非某个 Feature 本身需要两步才能说清楚，否则默认 1 次触发。

验收口径

进入 viewport→停在有意义的 Before 状态→用户 1 次轻操作→原动画自动演完

PASS 条件：用户能明确感到“是我触发了这个功能”，但不需要像真的剪辑软件一样完成一长串操作。
